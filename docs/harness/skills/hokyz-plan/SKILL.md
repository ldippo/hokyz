description: Plan a Hokyz game improvement into scoped local tasks with player outcomes and evidence gates. Use for game planning or preparing a Hokyz improvement burst.
---

Read `CONTEXT.md`, `docs/design/concept.md`, and `docs/harness/queue.md` from the
Hokyz root. Use roadmap status logs as history and inspect the relevant code.
Translate the user's requested outcome into independently verifiable vertical
slices in the local queue. Each task needs scope, acceptance checks, dependencies,
and expected simulation/browser evidence. Mark user-authorized work ready; record
speculative additions as proposed. Do not republish issues to an external tracker.
Do not invent a v4 milestone when the user has supplied no product direction.
Planning alone does not start execution; a request to plan and implement does.
